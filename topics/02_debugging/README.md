# Debugging

## 1. 디버깅이란?

디버깅(Debugging)은 프로그램에서 발생하는 오류를 찾아 원인을 확인하고 수정하는 과정이다.

프로그램에서 발생하는 오류는 크게 다음 두 가지로 나눌 수 있다.

### Syntax Error

문법 자체가 잘못된 경우이다.

예:

```python
print("Hello"
```

이런 오류는 Python 인터프리터나 IDE에서 바로 확인할 수 있다.

### Logic Error

문법에는 문제가 없지만 **프로그램이 개발자가 의도한 것과 다르게 동작하는 오류**이다.

예:

```python
answer = 10

for i in range(5):
    answer += i

print(answer)
```

문법적으로는 정상적으로 실행되지만, 개발자가 `answer`를 0부터 계산하려고 했다면 잘못된 결과가 나온다.

코딩 테스트에서는 이러한 **논리 오류를 찾아내는 것이 특히 중요하다.**

---

## 2. 왜 디버깅이 중요한가?

코딩 테스트에서는 다음과 같은 작은 실수로 오답이 발생하는 경우가 많다.

* 변수 초기화를 하지 않은 경우
* 반복문의 범위를 잘못 지정한 경우
* 잘못된 변수를 사용한 경우
* 출력 형식이나 자료형이 잘못된 경우
* 특정 예외 케이스를 고려하지 않은 경우

코드는 정상적으로 실행되기 때문에 단순히 코드를 읽는 것만으로는 오류를 찾기 어려울 수 있다.

이때 디버거를 사용해 프로그램을 한 줄씩 실행하면:

```text
현재 실행 위치
        ↓
변수 값 확인
        ↓
다음 코드 실행
        ↓
변수 값 변화 확인
        ↓
의도한 동작과 비교
```

하는 방식으로 논리 오류를 찾을 수 있다.

---

## 3. 기본적인 디버깅 방법

IDE의 디버거에서는 일반적으로 다음 기능을 사용한다.

### Breakpoint

프로그램 실행을 특정 코드에서 멈추기 위한 중단점이다.

```text
프로그램 실행
      ↓
Breakpoint
      ↓
실행 정지
```

프로그램을 멈춘 상태에서 현재 변수의 값과 프로그램 상태를 확인할 수 있다.

### Step Execution

코드를 한 줄씩 실행하면서 프로그램의 흐름을 확인한다.

주로 다음과 같은 동작을 사용한다.

* 한 줄 실행
* 함수 내부로 이동
* 함수 실행을 완료하고 반환
* 다음 Breakpoint까지 실행

IDE마다 이름과 단축키는 다를 수 있다.

### Variables

현재 시점의 변수 값을 확인한다.

예:

```text
i = 3
answer = 15
start = 2
end = 5
```

변수 값이 예상한 값과 다른 시점을 찾으면 오류 발생 위치를 추적할 수 있다.

---

# 4. 대표적인 논리 오류

강의에서는 디버깅을 통해 찾을 수 있는 대표적인 오류 네 가지를 다루었다.

---

## 4.1 변수 초기화 오류

반복해서 여러 테스트 케이스를 처리할 때 이전 결과가 다음 테스트에 남아 있는 경우이다.

### 잘못된 예

```python
answer = 0

for t in range(3):

    for i in range(5):
        answer += i

    print(answer)
```

`answer`가 한 번만 초기화되기 때문에 이전 테스트 결과가 다음 테스트에 누적된다.

### 수정

```python
for t in range(3):

    answer = 0

    for i in range(5):
        answer += i

    print(answer)
```

각 테스트 케이스를 시작할 때 필요한 변수를 다시 초기화해야 한다.

### 디버깅할 때 확인할 것

새로운 테스트 케이스가 시작되었는데도:

```text
answer = 0
```

이 아니라 이전 결과가 남아 있다면 초기화 위치를 확인한다.

---

# 5. 인덱스와 반복 범위 오류

반복문의 시작 또는 종료 범위를 잘못 지정하면 일부 데이터가 처리되지 않을 수 있다.

예를 들어 100개의 데이터를 처리해야 하는데:

```python
for i in range(10):
    ...
```

만 실행한다면 나머지 데이터는 처리되지 않는다.

또한 다음과 같은 실수가 자주 발생한다.

```text
N까지 반복해야 하는가?

N-1까지 반복해야 하는가?

N+1까지 포함해야 하는가?
```

Python의 `range()`는 끝 값을 포함하지 않는다는 점도 확인해야 한다.

```python
for i in range(5):
    print(i)
```

결과:

```text
0
1
2
3
4
```

따라서 인덱스와 반복 범위가 의도한 데이터 범위와 일치하는지 확인해야 한다.

---

# 6. 잘못된 변수 사용

비슷한 이름이나 의미를 가진 변수가 여러 개 있으면 다른 변수를 잘못 사용할 수 있다.

예를 들어:

```python
test_case = 5

for t in range(1, test_case + 1):
    print(test_case)
```

개발자가 현재 테스트 케이스 번호를 출력하려고 했다면 잘못된 코드이다.

`test_case`는 전체 테스트 케이스 개수이고 실제 현재 순번은 `t`이다.

따라서:

```python
print(t)
```

가 되어야 한다.

디버깅 중 Variables 창을 확인하면

```text
test_case = 5
t = 2
```

처럼 현재 각 변수에 어떤 값이 들어 있는지 확인할 수 있다.

---

# 7. 자료형과 출력 형식 오류

Python에서는 연산에 따라 자료형이 자동으로 변환될 수 있다.

특히 나눗셈에서 주의해야 한다.

## `/`

일반적인 나눗셈 결과를 반환한다.

```python
5 / 2
```

결과:

```text
2.5
```

정수끼리 계산하더라도 결과는 `float`가 된다.

```python
10 / 2
```

결과:

```text
5.0
```

## `//`

몫을 반환한다.

```python
5 // 2
```

결과:

```text
2
```

## `%`

나머지를 반환한다.

```python
5 % 2
```

결과:

```text
1
```

정리하면:

| 연산자  | 의미  | `5`와 `2`를 사용한 결과 |
| ---- | --- | ---------------: |
| `/`  | 나눗셈 |            `2.5` |
| `//` | 몫   |              `2` |
| `%`  | 나머지 |              `1` |

코딩 테스트에서는 숫자의 값뿐만 아니라 출력 형식도 정확해야 한다.

예를 들어 정답이:

```text
519
```

이어야 하는데:

```text
519.0
```

을 출력한다면 오답으로 처리될 수 있다.

# 8. 디버깅할 때 확인할 항목

코드가 예상대로 동작하지 않는다면 다음 순서로 확인한다.

### 1. 입력값 확인

```text
입력이 예상한 값으로 들어왔는가?
```

### 2. 변수 초기화 확인

```text
이전 반복 또는 테스트의 값이 남아 있지 않은가?
```

### 3. 반복 범위 확인

```text
반복문이 정확한 범위를 처리하고 있는가?
```

### 4. 인덱스 확인

```text
원하는 배열 위치를 접근하고 있는가?
```

### 5. 변수 확인

```text
현재 사용하고 있는 변수가 정말 의도한 변수인가?
```

### 6. 연산 결과와 자료형 확인

```text
int인가?
float인가?

연산 결과가 예상한 값인가?
```

### 7. 출력 확인

```text
문제에서 요구한 형식과 정확히 같은가?
```

# 9. 디버깅을 공부에 활용하기

디버깅은 자신의 코드에서 오류를 찾을 때뿐만 아니라 **알고리즘을 이해할 때도 활용할 수 있다.**

처음 보는 알고리즘 코드가 있다면:

```text
Breakpoint 설정
        ↓
한 줄씩 실행
        ↓
변수 변화 확인
        ↓
자료구조 상태 확인
        ↓
알고리즘의 동작 과정 이해
```

하는 방식으로 분석할 수 있다.

예를 들어 앞으로 공부할:

* Bubble Sort
* DFS
* BFS
* Binary Search
* Dijkstra
* Dynamic Programming

등의 알고리즘도 디버거를 이용해 한 단계씩 실행하면 코드의 흐름을 이해하는 데 도움이 된다.

---

# 10. 핵심 정리

## 디버깅의 목적

```text
코드를 실행
    ↓
Breakpoint에서 중단
    ↓
현재 변수 상태 확인
    ↓
한 줄씩 실행
    ↓
예상값과 실제값 비교
    ↓
논리 오류 발견
```

## 자주 발생하는 오류

```text
변수 초기화 오류
인덱스·반복 범위 오류
잘못된 변수 사용
자료형·출력 형식 오류
```

## 기억할 것

* 코드가 실행된다고 해서 올바른 코드는 아니다.
* 논리 오류는 프로그램이 의도와 다르게 동작하는 오류이다.
* Breakpoint와 Variables를 이용해 변수의 변화를 확인한다.
* 코드를 한 줄씩 실행하며 예상값과 실제값을 비교한다.
* 테스트 케이스가 바뀔 때 변수 초기화를 확인한다.
* 반복문의 시작과 끝 범위를 확인한다.
* 비슷한 변수를 잘못 사용하지 않았는지 확인한다.
* Python의 `/`, `//`, `%` 차이를 주의한다.
* 디버깅은 오류 수정뿐 아니라 다른 사람의 코드와 알고리즘을 이해하는 데도 사용할 수 있다.
