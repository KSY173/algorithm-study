# Time Complexity

## 1. 시간 복잡도란?

시간 복잡도(Time Complexity)는 **주어진 문제를 해결하기 위해 필요한 연산 횟수**를 나타낸다.

알고리즘마다 입력 데이터의 크기 `N`이 증가했을 때 필요한 연산 횟수가 다르기 때문에, 시간 복잡도는 문제에 사용할 알고리즘을 선택하는 중요한 기준이 된다.

---

## 2. 시간 복잡도 표기법

시간 복잡도는 대표적으로 다음 세 가지 방법으로 표현할 수 있다.

| 표기법           | 의미      |
| ------------- | ------- |
| Big Ω (Omega) | 최선의 경우  |
| Big Θ (Theta) | 평균적인 경우 |
| Big O         | 최악의 경우  |

예를 들어 `N`개의 데이터에서 특정 값을 앞에서부터 찾는다고 생각해보자.

* 첫 번째 데이터가 찾는 값이라면 → `Ω(1)`
* 평균적으로 중간쯤에서 찾는다면 → `Θ(N/2)`
* 마지막 데이터에서 찾는다면 → `O(N)`

코딩 테스트에서는 여러 테스트 케이스를 모두 통과해야 하므로 **최악의 경우를 나타내는 Big O를 기준으로 판단하는 것이 중요하다.**

---

## 3. 입력 데이터 크기와 시간 복잡도

시간 복잡도를 판단할 때는 문제에서 주어진 **입력 데이터의 최대 크기**를 확인해야 한다.

문제의 입력 범위가

```text
1 ≤ N ≤ 1,000,000
```

이라면 시간 복잡도를 계산할 때는 최악의 경우인

```text
N = 1,000,000
```

을 기준으로 생각한다.

강의에서는 Python의 연산 속도를 대략 초당 2천만~1억 회 정도로 보고, 보수적으로 판단할 때는 **1초당 약 2천만 회**를 기준으로 설명했다.

예를 들어 제한 시간이 2초라면:

```text
약 40,000,000번 이하의 연산
```

으로 해결할 수 있는지를 기준으로 알고리즘을 판단할 수 있다.

> 실제 실행 속도는 연산 종류와 환경에 따라 달라질 수 있으므로, 이 값은 코딩 테스트에서 알고리즘 가능성을 빠르게 판단하기 위한 대략적인 기준으로 사용한다.

---

## 4. 알고리즘 선택에 시간 복잡도 사용하기

입력 데이터가 최대

```text
N = 1,000,000
```

이고 제한 시간이 2초라고 가정한다.

### O(N²)

예를 들어 버블 정렬의 시간 복잡도가 `O(N²)`이라면:

```text
1,000,000²
= 1,000,000,000,000
```

정도의 연산이 필요하다.

이는 약 4천만 번이라는 기준을 크게 초과하므로 적절하지 않다.

### O(N log N)

반면 `O(N log N)` 알고리즘이라면:

```text
N = 1,000,000
log₂N ≈ 20

N log₂N
≈ 20,000,000
```

정도의 연산이 필요하다.

따라서 같은 문제에서도 `O(N²)` 알고리즘보다 `O(N log N)` 알고리즘이 적합할 가능성이 높다.

즉, 문제를 풀기 전에

```text
입력 데이터 최대 크기
        ↓
시간 제한
        ↓
사용하려는 알고리즘의 시간 복잡도
        ↓
사용 가능한 알고리즘인지 판단
```

하는 습관이 중요하다.

---

## 5. 코드의 시간 복잡도 구하기

코드의 시간 복잡도를 구할 때는 크게 두 가지를 확인한다.

### 5.1 상수는 제외한다

다음 코드가 있다고 가정한다.

```python
for i in range(n):
    pass
```

연산 횟수는 약 `N`이므로:

```text
O(N)
```

이다.

반복문이 세 개라면:

```python
for i in range(n):
    pass

for i in range(n):
    pass

for i in range(n):
    pass
```

약 `3N`번 실행된다.

하지만 시간 복잡도에서는 상수를 제외하므로:

```text
O(3N) → O(N)
```

으로 표현한다.

---

### 5.2 가장 많이 중첩된 부분을 확인한다

다음과 같이 반복문이 중첩되어 있다면:

```python
for i in range(n):
    for j in range(n):
        pass
```

안쪽 반복문이 `N`번 실행되고 이것이 다시 `N`번 반복되므로:

```text
N × N = N²
```

따라서 시간 복잡도는:

```text
O(N²)
```

이다.

`O(N)`과 `O(N²)`은 입력 크기가 커질수록 실행 시간 차이가 매우 커진다.

따라서 코드에서 시간 초과가 발생하면 **가장 많이 중첩된 반복이나 탐색 로직부터 확인해야 한다.**

---

## 6. 시간 복잡도를 이용한 코드 개선

예를 들어 다음과 같은 구조가 있다고 하자.

```text
N번 반복
    ↓
매번 N개의 데이터에서 특정 값 탐색
```

바깥 반복문이 `N`번이고 내부 탐색도 최악의 경우 `N`번이라면:

```text
O(N²)
```

이 된다.

강의에서는 이를 다음과 같이 개선하는 예를 설명했다.

```text
데이터 정렬
O(N log N)

        ↓

N번 반복하면서
Binary Search 수행
O(N log N)
```

전체적으로 보면:

```text
O(N log N) + O(N log N)
= O(2N log N)
= O(N log N)
```

이 된다.

즉, 비효율적인 탐색 구조를 다른 알고리즘으로 변경함으로써

```text
O(N²)
        ↓
O(N log N)
```

으로 개선할 수 있다.

---

## 7. 시간 복잡도를 보는 순서

코딩 테스트 문제를 만나면 다음 순서로 확인한다.

1. 입력 데이터의 최대 크기 `N`을 확인한다.
2. 문제의 시간 제한을 확인한다.
3. 사용할 알고리즘의 Big O 시간 복잡도를 확인한다.
4. 최대 `N`을 시간 복잡도에 대입해본다.
5. 제한 시간 안에 처리 가능한지 판단한다.
6. 시간 초과가 예상된다면 더 낮은 시간 복잡도의 알고리즘을 찾는다.

---

## 8. 핵심 정리

### 문제를 분석할 때

```text
최대 입력 크기
+
시간 제한
+
알고리즘의 Big O
        ↓
사용 가능한 알고리즘 판단
```

### 내가 작성한 코드를 분석할 때

```text
반복 및 탐색 구조 확인
        ↓
가장 많이 중첩된 부분 확인
        ↓
시간 복잡도 계산
        ↓
비효율적인 부분 개선
```

### 기억할 것

* 코딩 테스트에서는 주로 **Big O**, 즉 최악의 경우를 기준으로 판단한다.
* 입력 범위에서는 **최대 데이터 크기**를 기준으로 계산한다.
* 시간 복잡도에서는 상수를 제외한다.
* 가장 높은 차수의 항이 전체 시간 복잡도를 결정한다.
* 중첩 반복문과 반복되는 탐색 로직을 특히 주의한다.
* 입력 크기가 커질수록 `O(N)`, `O(N log N)`, `O(N²)` 사이의 성능 차이가 크게 증가한다.
* 시간 복잡도는 사용할 알고리즘을 선택하는 기준이자, 비효율적인 코드를 찾는 도구로 사용할 수 있다.
